# Warcraft model rendering

- Render team colour and team glow with the actual Warcraft III `TeamColorNN` and `TeamGlowNN` textures for the selected player colour. Do not substitute flat RGB fills or procedural glow approximations.
- Preserve authored team-glow geometry and effects in live previews and captured model images. Transparent captures must retain the glow without an opaque background rectangle.
- Verify colour changes on the model itself before publishing; changing a card background does not verify a team-colour change.

## Model file additions

- When adding a user-supplied model file to the catalogue, preserve the provided description or lore and credit every supplied source model. The `By:` list is for the finished model's authors; source-model authors belong under `Model Base` or the relevant parts credit, not automatically in `By:` on the card, page, or Credits tab. Only add a source author to `By:` when explicitly requested as a co-author of the finished model. In credits, show linked model titles and linked author names; never print raw source URLs.
- In the Credits tab, identify the original model using the existing format: the linked `By:` author list, a bold `Model Base` heading, then `<linked model title> by <linked author>`. Store this as `Model Base - <model title> by <author>` in the catalogue's credits text so the shared renderer produces the heading and linked content. Add `/ Further edited by <linked author>` only when that contribution is supplied. When the user provides model credits without explicitly identifying the original/base model, ask which model is the base. Do not infer this from link order, a co-author request, or the model's appearance. Continue independent preparation while waiting; do not guess the base-model attribution.
- A supplied model plus text and credit links is a complete request to create the standard model card and page. Follow the existing catalogue design automatically for any model. Finish the image, working preview, authors, credits, description, model download, and generated share page; a catalogue row or broken image is not a deliverable.
- Hive model and author links supplied as credits are attribution references. Read their titles and authors; do not download those models, substitute them for the supplied file, or treat them as missing attachments.
- Upload the supplied model as is. Copy its bytes, retain its native texture paths, and verify SHA-256 against the original and the live download. Native textures are rendering assets for the card/site preview, not extra files to put in the model download. Do not rewrite the MDX, bundle native textures into a download ZIP, or invent a replacement texture.
- Resolve native Warcraft texture dependencies yourself from the site's existing mappings and local Warcraft archives. Missing from `dist/textures.json` does not mean missing from Warcraft or that the user must provide the texture. Read every texture reference from the actual model, including effects. Only ask about a genuinely unavailable custom dependency after checking the supplied files and local sources.
- Use `node tools/model-textures.mjs <catalogue-id>` to resolve missing native rendering textures. It uses the existing MDLxL archive readers with local classic MPQs first and local CASC second; it never downloads a Hive model. Machine paths can be passed with `--mdlxl`, `--archives`, and `--game`. On this machine the sources are `D:/WarcraftStuff` and `D:/Warcraft III`. Use native Windows paths and the established reader API; do not invent interop signatures if extraction fails.
- Compare the local renderer with current `gh-pages` before capture; a dirty checkout can contain older rendering code. Capture with the current published renderer and actual native team textures. Capture only the requested model through `/__portraits.html?models=<catalogue-id>` on `node server.mjs`, inspect the actual PNG and model page, and verify normal mouse rotation, textures, team colour, authored glow/effects, and download links. Run `node tools/model-pages.mjs` and `node tools/check-project.mjs`. Preserve other cards and authored model bytes.
- For model-card requests, completing the card includes publishing it to LowPolyWorks unless the user explicitly says offline, draft, or review first. Once publication is authorized, finish it without asking again. Apply only the requested changes on current remote source and `gh-pages`, refresh the affected cache keys and generated pages, wait for Pages, then verify the public card image, page, credits, preview, and original model download. Keep progress and the final response short; report completion with the live link, not repeated apologies or offers to continue.
